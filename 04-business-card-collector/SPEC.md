# 명함 수집 및 정리 자동화 SPEC

명함 정보를 사진 또는 설문조사 두 가지 방식으로 제공받아, 하나의 Google Sheets에 정리된 연락처 데이터베이스로 축적하는 서비스입니다.

## 목적
- 명함 정보를 두 가지 입력 경로로 수집합니다.
  1. 명함 사진 (로컬 폴더에 저장된 이미지 파일, OCR로 텍스트 추출 필요)
  2. 설문조사 응답 (Google Forms로 담당자 또는 상대방이 직접 입력한 텍스트, 이미 구조화되어 있어 추출 불필요)
- 두 경로의 결과를 하나의 Google Sheets 안에서 관리합니다.
- 사진에서 추출한 정보와 사람이 직접 입력한 정보를 같은 스키마로 정규화해, 이후 검색·필터링·연락처 활용이 가능하게 합니다.

## 입력 경로
두 경로는 서로 독립된 파이프라인으로 동작하고, 결과만 같은 시트(명함 DB 탭)에 모입니다. 하나의 Form에 사진 업로드와 텍스트 입력을 함께 두지 않습니다.

- **사진 경로**: 담당자가 명함 사진 파일을 로컬 폴더(예: `명함사진/미처리`)에 모아두면, 로컬에서 실행하는 스크립트가 이 폴더를 읽어 처리합니다. Drive 업로드 과정을 거치지 않습니다.
- **설문 경로**: 기존 Google Forms 설문(텍스트 입력 전용, 사진 첨부 항목 없음)에 제출된 응답이 "설문지 응답" 시트에 그대로 쌓입니다. 이 폼/시트는 이번 변경과 무관하게 그대로 둡니다.

## 사진 제공 시 데이터 추출·저장 로직 (핵심 검토 대상)

로컬 스크립트를 수동 실행하거나 OS 스케줄러(cron / 작업 스케줄러)로 주기 실행하면, 지정한 로컬 폴더를 스캔해 아래 순서로 처리합니다.

1. **대상 파일 탐색**
   - 지정 폴더(`명함사진/미처리`) 안의 이미지 파일(jpg, png 등)을 나열합니다.
   - 이미 처리한 파일은 다시 처리하지 않도록, 처리 완료 시 파일을 `명함사진/처리완료` 폴더로 이동합니다. 별도 처리 이력 DB 없이 폴더 위치만으로 처리 여부를 구분합니다.

2. **OCR 텍스트 추출**
   - 로컬에서 Tesseract OCR(한글 언어팩 포함)로 이미지를 텍스트로 변환합니다. 외부로 이미지를 전송하지 않는 방식입니다.
   - 정규식으로 패턴이 명확한 항목만 우선 추출합니다: 이메일, 휴대폰번호(010-…), 유선번호, 웹사이트 URL.
   - 이름/회사/직책처럼 레이아웃(글자 크기·위치)에 의존하는 항목은 OCR 텍스트만으로는 정확히 구분하기 어렵습니다. 자동으로 최선의 후보를 채워 넣되, **처리상태를 "검토필요"로 표시**하고 OCR 원문 전체를 별도 컬럼에 그대로 보존합니다. 담당자가 원문을 보고 수동으로 바로잡는 것을 기본 전제로 합니다.
   - 원본 이미지 파일은 삭제하지 않고 `처리완료` 폴더에 보관하며, 명함 DB 행에는 해당 로컬 파일 경로(파일명)를 참조용으로 기록합니다.

3. **중복 검사**
   - 이메일 또는 휴대폰번호를 기준으로 명함 DB 기존 행(사진·설문 출처 모두 포함)과 대조합니다.
   - 일치하는 행이 있으면 **자동 병합하지 않고** "중복후보"로 표시만 하고, 기존 행 위치를 함께 기록합니다. 자동 병합은 오탐으로 인한 데이터 손실 위험이 커서 Phase 1에서는 배제합니다.

4. **명함 DB 기록 + 로그**
   - Google Sheets API로 명함 DB 탭에 신규 행을 추가합니다.
   - 로그 탭에 실행 결과(처리 건수, 검토필요 건수, 중복후보 건수, 오류)를 기록합니다.

## 설문 경로 처리 (변경 없음)
- 기존 Google Forms 제출 시 Apps Script `onFormSubmit` 트리거가 실행되어, 텍스트 필드 값을 그대로 명함 DB 컬럼에 매핑합니다.
- 사람이 직접 입력했으므로 처리상태는 "확인완료"로 표시하고 검토 대상에서 제외합니다.
- 중복 검사 로직(이메일/휴대폰 대조, 자동 병합 없음)은 사진 경로와 동일하게 적용합니다.

## 데이터 구조

- **설문지 응답 탭** (Google Forms 자동 생성, 텍스트 입력 전용, 원본 그대로 보존)
  - 제출일시, 이름, 회사, 직책, 휴대폰, 이메일 등 Form 질문 그대로

- **명함 DB 탭** (정리된 마스터 데이터, 사진·설문 공통)
  - `등록일시 | 데이터출처(사진/설문) | 처리상태(검토필요/확인완료) | 이름 | 회사 | 부서 | 직책 | 휴대폰 | 유선전화 | 이메일 | 주소 | 웹사이트 | 로컬파일경로 | OCR원문 | 중복후보행 | 원본응답행번호 | 담당자메모`
  - `로컬파일경로`, `OCR원문`은 사진 경로 건에만 값이 들어갑니다.

- **로그 탭**
  - `실행일시 | 처리건수 | 사진경로건수 | 설문경로건수 | 검토필요건수 | 중복후보건수 | 오류내용`

## 기술 스택 요약
- 사진 경로 실행 환경: 로컬 Python 스크립트 (수동 실행 또는 OS 스케줄러로 주기 실행)
- 이미지 OCR (Phase 1): Tesseract OCR(`pytesseract`) 로컬 실행 — 무료, 외부 전송 없음
- 이미지 OCR (Phase 2 검토): Naver Clova OCR 명함인식 API 또는 Google Cloud Vision API `DOCUMENT_TEXT_DETECTION` — 텍스트 위치 정보를 활용해 이름/회사/직책 자동 구분 정확도를 높일 목적. Tesseract 정확도가 운영 중 부족하다고 판단되면 도입 검토. 이 경우도 이미지는 API로 직접 전송하며 별도 Drive 업로드는 거치지 않습니다.
- 명함 DB 기록: Google Sheets API (서비스 계정 인증, `gspread` 또는 `google-api-python-client`)
- 설문 경로: 기존과 동일하게 Google Forms + Apps Script `onFormSubmit` 트리거

## 인증/보안 전략
- 명함 데이터는 이름, 연락처, 이메일 등 **개인정보를 포함**하므로 컨퍼런스 수집 기획과 달리 접근 통제가 필요합니다.
- 로컬 명함 사진 폴더 접근은 담당자 PC로 제한합니다.
- Google Sheets API 서비스 계정 키 파일은 로컬 머신에만 보관하고 저장소에 커밋하지 않으며, 해당 스프레드시트에 대한 최소 권한만 부여합니다.
- Apps Script 프로젝트 편집 권한은 운영 담당자만 보유합니다.
- Phase 2에서 외부 OCR API 키를 사용할 경우 환경변수 또는 로컬 설정 파일로 관리하고 코드에 하드코딩하지 않습니다.

## 제외 범위 (Phase 1)
- 중복 명함 자동 병합 (검토 후 수동 병합만 지원)
- 명함 DB와 외부 CRM 연동
- 명함 수집 후 자동 인사 메일 발송
- 영문/다국어 명함의 OCR 정확도 보장 (Phase 1은 국문 명함 기준, Phase 2에서 OCR API 도입 시 함께 검토)
