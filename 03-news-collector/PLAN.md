# 키워드 기반 뉴스·보도자료 자동 수집 PLAN

기준 문서: `SPEC.md`

이 계획은 Google Apps Script와 Google Sheets만으로 Phase 1을 먼저 완성하는 것을 기준으로 합니다. Claude API 요약 고도화, 콘텐츠 후보 자동 제안, 알림 기능은 Phase 2에서 다룹니다.

> Phase 2 아키텍처 메모: AI 추론에 쓰는 사내 게이트웨이(`litellm.ops.raonops.com`)는 사내망에서만 도달 가능하고 Apps Script(구글 서버)에서는 닿지 않는다(확인 완료: `Address unavailable`). 그래서 Phase 2는 **하이브리드**로 간다 — Apps Script 는 데이터 브릿지 Web App 만 제공하고, 실제 추론은 사내망 **로컬 러너(Node, `runner/summarize.mjs`)** 가 담당한다.

## 개발 원칙
- Phase 1은 Google Sheets 안에서 끝냅니다.
- 키워드는 한 번에 많이 등록하지 않고, 1~2개로 수집 로직을 먼저 검증합니다.
- 기업 뉴스룸을 항상 먼저 조회하고, 뉴스룸이 없거나 결과가 0건일 때만 네이버로 넘어갑니다.
- 같은 키워드를 반복 수집해도 뉴스 수집 탭에 중복 행이 쌓이지 않아야 합니다.
- 모든 자동 실행은 로그 탭에 결과를 남깁니다.

## Phase 1 개발 단위

### P1-01. Google Sheets 기본 구조 생성
- 목표: 서비스가 사용할 탭과 헤더를 자동 생성합니다.
- 구현 항목
  - `키워드관리`/`뉴스수집` 탭을 트랙(`기술`, `경쟁사`, `컨퍼런스`)별로 각각 생성 (예: `키워드 관리(기술)`, `키워드 관리(경쟁사)`)
  - `일일요약` 탭 생성 (트랙 공통)
  - `주간콘텐츠후보` 탭 생성 (트랙 공통)
  - `로그` 탭 생성 (트랙 공통)
  - 헤더가 없을 때만 생성되도록 멱등 처리
- 주요 함수
  - `setup()`
  - `ensureSheets_()`
  - `ensureHeaders_()`
- 완료 기준
  - 빈 시트에서 `setup()` 실행 시 필요한 탭과 헤더가 생성됩니다.
  - 다시 실행해도 기존 데이터가 삭제되거나 헤더가 중복 생성되지 않습니다.

### P1-02. 키워드 관리 기능
- 목표: 수집할 키워드 목록을 시트에서 관리합니다.
- `키워드관리` 컬럼
  - `사용여부`
  - `키워드`
  - `기업뉴스룸 URL`
  - `카테고리`
  - `등록일`
  - `비고`
- 구현 항목
  - 사용여부가 `Y`인 행만 수집
  - `기업뉴스룸 URL`이 비어 있으면 네이버 검색만 수행하도록 판단
- [정책 변경] 키워드입력 탭 폐지. 별도 입력창 없이 `키워드관리` 탭 한 곳에서 직접 행을 추가/수정한다(동기화 로직 불필요).
- 주요 함수
  - `getEnabledKeywords_()`
  - `hasNewsroom_(keywordRow)`
- 완료 기준
  - 담당자가 `키워드관리` 탭에서 직접 키워드를 추가하거나 비활성화할 수 있습니다.
  - 뉴스룸 URL 유무에 따라 수집 경로가 올바르게 갈립니다.

### P1-03. 기업 뉴스룸 수집기 구현
- 목표: 키워드에 뉴스룸 URL이 등록된 경우 뉴스룸에서 최신 게시물을 가져옵니다.
- 구현 항목
  - 공통 fetch 함수
  - 뉴스룸 목록 페이지에서 제목, 발행일, 링크 추출
  - 페이지 구조가 달라 파싱 실패 시 0건으로 처리하고 네이버로 넘어가도록 표시
- 주요 함수
  - `fetchHtml_(url)`
  - `collectFromNewsroom_(keywordRow)`
  - `parseNewsroomList_(html)`
- 완료 기준
  - 뉴스룸에서 최소 `제목`, `발행일`, `링크`를 추출합니다.
  - 파싱 실패는 전체 실행을 중단시키지 않고 로그에 남깁니다.

### P1-04. 네이버 뉴스 검색 수집기 구현
- 목표: 뉴스룸이 없거나 결과가 없는 키워드를 네이버 뉴스 검색으로 보완합니다.
- 구현 항목
  - 네이버 뉴스 검색 결과 페이지 fetch
  - 제목, 언론사, 발행일, 링크 추출
  - 보도자료성 결과 우선 정렬(가능한 범위 내)
- 주요 함수
  - `collectFromNaver_(keyword)`
  - `parseNaverNewsList_(html)`
- 완료 기준
  - 네이버 검색 결과에서 최소 `제목`, `언론사`, `발행일`, `링크`를 추출합니다.
  - 검색 결과 0건이어도 오류 없이 빈 배열을 반환합니다.

### P1-05. 기사 데이터 정규화 및 중복 제거
- 목표: 뉴스룸과 네이버에서 가져온 데이터를 같은 컬럼 구조로 맞추고 중복을 제거합니다.
- 구현 항목
  - 날짜 형식 통일
  - 언론사 값이 없으면 뉴스룸 발행 주체명으로 대체
  - 링크(URL) 기준 중복 판단
  - 동일 사안(같은 보도자료를 여러 매체가 받아쓴 기사) 묶기: 제목+메타설명을 2-gram 집합으로 만들어 overlap coefficient로 비교, 임계값 이상이면 하나로 묶고 가장 먼저 발행된 기사를 대표로 남김
- 주요 함수
  - `normalizeArticle_(rawArticle, keyword)`
  - `dedupeArticles_(articles)`
  - `groupDuplicateStories_(articles)`
- 완료 기준
  - 같은 링크의 기사는 한 번만 남습니다.
  - 날짜 형식이 다른 소스에서도 동일한 포맷으로 저장됩니다.
  - 서로 다른 매체가 같은 사안을 다르게 표현해도 하나로 묶여 `기사건수`에 반영됩니다.

### P1-06. 규칙 기반 요약 및 저장
- 목표: AI API 없이도 기본 요약을 생성하고 `뉴스수집` 탭에 누적 저장합니다.
- 구현 항목
  - 기사 스니펫에서 핵심 문장 추출
  - 요약 생성일시 기록
  - 신규 기사만 새 행으로 추가 (중복 링크는 건너뜀)
- 주요 함수
  - `summarizeByRule_(article)`
  - `appendArticles_(articles)`
  - `findExistingLinks_()`
- 완료 기준
  - 모든 저장 기사에 요약과 요약생성일시가 채워집니다.
  - 같은 기사를 다시 수집해도 중복 행이 생기지 않습니다.

### P1-07. 수집 결과 집계
- 목표: 키워드·수집 회차 기준 기사건수를 계산해 함께 기록합니다.
- 구현 항목
  - 같은 수집 회차·키워드로 저장된 기사 수 카운트
  - `기사건수` 컬럼에 반영
- 주요 함수
  - `countArticlesByRun_(keyword, runAt)`
- 완료 기준
  - 각 행의 `기사건수`가 실제 저장된 기사 수와 일치합니다.

### P1-08. 자동 실행 트리거와 수동 실행 메뉴
- 목표: 매일 오전 8시 자동 수집하고, 필요 시 수동 실행도 가능하게 합니다.
- 구현 항목
  - 시간 기반 트리거 생성
  - 기존 중복 트리거 제거
  - Google Sheets 상단 메뉴 추가 (`뉴스 수집` 메뉴, `주간콘텐츠후보` 메뉴)
  - 수동 실행 함수 제공
  - 주간콘텐츠후보 수동 생성 요청: 스크립트 속성에 요청 시각을 남기면 로컬 러너가 폴링해 처리(연동 전이면 다음 월요일 자동 실행 때 처리)
- 주요 함수
  - `installTriggers_()`
  - `removeExistingTriggers_()`
  - `onOpen()`
  - `runNow()`
  - `collectScheduled()`
  - `requestWeeklyCandidatesNow()`
- 완료 기준
  - `setup()` 실행 후 매일 오전 8시 트리거가 등록됩니다.
  - 메뉴에서 수동 수집을 실행할 수 있습니다.

### P1-09. 실행 로그와 오류 처리
- 목표: 자동 수집 결과를 나중에 확인할 수 있게 남깁니다.
- 구현 항목
  - 실행 시작/종료 시간 기록
  - 대상 키워드 수, 신규 기사 수 기록
  - 오류 수와 오류 내용 기록
  - 키워드별 실패가 전체 실패로 이어지지 않게 처리
- 주요 함수
  - `appendRunLog_(result)`
  - `safeCollectKeyword_(keywordRow)`
- 완료 기준
  - 수집 실패 원인을 로그 탭에서 확인할 수 있습니다.
  - 일부 키워드가 실패해도 나머지 키워드는 계속 처리됩니다.

### P1-10. 검증 및 운영 점검
- 목표: 실제 운영 전에 반복 실행 안정성을 확인합니다.
- 검증 항목
  - 빈 시트에서 최초 설치
  - 수동 수집 1회 실행 (뉴스룸 있는 키워드 1개, 없는 키워드 1개)
  - 같은 데이터 재실행 시 중복 없음
  - 뉴스룸 파싱 실패 시 네이버로 정상 대체되는지 확인
  - 로그 탭 기록 확인
- 완료 기준
  - 담당자가 `setup()`과 `runNow()`만으로 설치와 테스트를 완료할 수 있습니다.
  - 운영 문서에 설치, 테스트, 트러블슈팅 절차가 정리됩니다.

## Phase 2 개발 단위

### P2-01. 데이터 브릿지 Web App + 로컬 러너 골격
- 목표: 사내망 로컬 러너가 시트 데이터를 안전하게 주고받을 창구(Web App)와, 게이트웨이 호출·응답 파싱을 담당할 러너 골격을 만듭니다.
- 구현 항목 (Apps Script Web App)
  - `doGet`: `todayNews`(오늘 수집분 키워드별 그룹), `recentSummaries&days=N`(최근 N일 일일요약) 반환
  - `doPost`: `dailySummary`, `weeklyCandidates` 결과를 시트에 기록
  - 스크립트 속성 `WEBAPP_TOKEN` 과 요청 `token` 파라미터 일치 검증
  - 배포: 웹 앱(실행: 나 / 액세스: 모든 사용자)
- 구현 항목 (로컬 러너 `runner/summarize.mjs`, Node 내장 fetch, 의존성 0)
  - 게이트웨이(`/v1/chat/completions`, Bearer) 호출, `choices[0].message.content` 추출 후 ```json 코드펜스 제거해 JSON 파싱
  - Web App `doGet`/`doPost` 클라이언트, `.env` 기반 설정(`--env-file`)
  - 네트워크 없이 순수 로직만 확인하는 `selfcheck` 명령
- 주요 함수/엔드포인트
  - Apps Script: `doGet(e)`, `doPost(e)`, `checkToken_(e)`, `writeDailySummary_(items)`, `writeWeeklyCandidates_(items)`
  - 러너: `callGateway()`, `parseClaudeJson()`, `bridgeGet()`, `bridgePost()`
- 완료 기준
  - 잘못된 토큰 요청은 `unauthorized` 로 거부됩니다.
  - 러너 `selfcheck` 가 통과합니다.

### P2-02. 일일요약 자동 생성
- 목표: 그날 `뉴스수집` 탭에 쌓인 기사를 키워드별로 묶어 게이트웨이로 요약하고 `일일요약` 탭에 기록합니다.
- `일일요약` 컬럼: `수집범위 | 키워드 | 기사건수 | AI요약 | 생성일시`
- 구현 항목
  - Apps Script: `doGet?action=todayNews` 가 수집일시가 오늘인 행을 키워드별 그룹으로 반환
  - 러너: 그룹을 프롬프트로 구성해 게이트웨이 호출 → 응답(JSON: keyword, summary) → `doPost?action=dailySummary` 로 기록
- 주요 함수
  - Apps Script: `getTodayNewsRows_()`, `groupArticlesByKeyword_(rows, ...)`, `writeDailySummary_(items)`
  - 러너: `buildDailySummaryPrompt(grouped)`, `runDaily()`
- 완료 기준
  - 당일 수집 기사가 있으면 키워드별 요약이 일일요약 탭에 쌓입니다.
  - 당일 수집 기사가 없으면 러너가 0건으로 건너뜁니다.

### P2-03. 주간 콘텐츠 후보 자동 제안
- 목표: 최근 7일 `일일요약`을 모아 게이트웨이로 블로그 콘텐츠 후보 5~7건을 생성해 `주간콘텐츠후보` 탭에 기록합니다. "일주일 치를 다 채워야만" 생성되지 않도록, 일일요약이 부족하면 그때까지 쌓인 원본 기사로 대체합니다.
- 구현 항목
  - Apps Script: `doGet?action=recentSummaries&days=7` 가 최근 7일 일일요약 반환
  - Apps Script: `doGet?action=weekNews&days=7` 가 최근 7일 뉴스수집 원본을 키워드별로 그룹 반환 (일일요약 폴백용)
  - 러너: 1순위로 `recentSummaries` 사용, 비어 있으면(예: 설치 직후라 일일요약이 하루치도 없음) `weekNews`를 키워드별 요약 형태로 변환해 대체 → "라온시큐어 브랜드 마케터" 관점 프롬프트로 게이트웨이 호출(title/keywords/reason/tieIn) → `doPost?action=weeklyCandidates` 로 기록(주차범위 + 순위 부여)
- 주요 함수
  - Apps Script: `getRecentSummaries_(days)`, `getRecentNewsRows_(days)`, `newsRowColumns_()`, `writeWeeklyCandidates_(items)`
  - 러너: `buildWeeklyCandidatePrompt(summaries)`, `weekNewsToSummaries(grouped)`, `runWeekly()`
- 완료 기준
  - 최근 7일 일일요약이 있으면 5~7건의 후보가 자동 생성되어 담당자가 검토·수정할 수 있는 상태로 쌓입니다.
  - 일일요약이 없어도 최근 7일 수집 기사가 있으면 그것만으로 후보가 생성됩니다.
  - 최근 7일 일일요약도 수집 기사도 전혀 없을 때만 러너가 0건으로 건너뜁니다.
- 실행 제약
  - 러너는 사내망(VPN 포함) 안에서 실행해야 게이트웨이에 도달합니다. 주 1회라 수동 실행으로 충분하며, 정기화 시 사내망 상시 연결 환경에서 `cron`/`launchd` 로 예약합니다.

### P2-04. 알림 기능
- 신규 기사 수집 시 담당자에게 이메일 또는 Slack으로 알립니다.
- 주간 콘텐츠 후보 초안이 생성되면 별도로 알립니다.

### P2-05. 수집 범위 확장
- 네이버 외 다른 포털(다음 등) 수집을 검토합니다.
- 검색 API 기반의 추가 수집을 검토합니다.
- JavaScript 렌더링이 필요한 뉴스룸은 Apps Script 단독 처리 대신 별도 수집 방식을 검토합니다.

## Phase 1 산출물
- Apps Script 코드
- Google Sheets 탭 구조 (`키워드관리`, `뉴스수집`, `일일요약`, `주간콘텐츠후보`, `로그`)
- 매일 오전 8시 자동 실행 트리거
- 수동 실행 메뉴
- 설치 및 테스트 안내 문서

## Phase 1 완료 기준
- 담당자가 Google Sheets에서 `setup()`을 1회 실행해 초기 설치를 완료할 수 있습니다.
- `runNow()` 실행 시 뉴스룸 또는 네이버에서 최소 1건 이상 기사가 수집됩니다.
- 같은 수집을 반복 실행해도 `뉴스수집` 탭에 중복 행이 생기지 않습니다.
- 뉴스룸에 결과가 없는 키워드는 네이버 검색으로 정상 대체됩니다.
- 자동 실행 결과가 `로그` 탭에 기록됩니다.
- 담당자가 `키워드관리` 탭에서 키워드를 직접 추가·비활성화할 수 있습니다.
