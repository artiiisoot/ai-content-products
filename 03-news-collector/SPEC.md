# 키워드 기반 뉴스·보도자료 자동 수집 SPEC

등록된 키워드를 기준으로 기업 뉴스룸과 네이버(포털) 보도자료를 자동으로 수집하고, Google Sheets에 정리해 주간 콘텐츠 후보 선정까지 이어지는 서비스입니다.

## 목적
- 담당자가 등록한 키워드별로 관련 뉴스·보도자료를 주기적으로 자동 수집합니다.
- 기업 뉴스룸을 우선 수집하고, 뉴스룸이 없거나 결과가 없는 키워드는 네이버 뉴스/보도자료 검색으로 보완합니다.
- 수집된 기사를 Google Sheets에 누적 기록해 검색·필터링·검토가 가능하게 합니다.
- 수집된 기사를 바탕으로 주간 콘텐츠 후보(제목, 관련 키워드, 라온시큐어 연결 포인트)를 선정할 수 있게 합니다.
- 담당자가 여러 사이트를 직접 방문하지 않아도 키워드별 최신 보도 현황을 빠르게 확인할 수 있게 합니다.

## 핵심 기능 요약
- 세 개의 독립된 수집 트랙: `기술`, `경쟁사`, `컨퍼런스`
  - 트랙마다 키워드관리/뉴스수집 탭이 별도로 존재합니다(예: `키워드 관리(기술)`, `키워드 관리(경쟁사)`).
  - [정책 변경] 키워드입력 탭은 폐지했습니다. 담당자가 키워드관리 탭에 직접 행을 추가/수정합니다(별도 동기화 불필요).
  - 일일요약/주간콘텐츠후보/로그 탭은 세 트랙 공통으로 사용합니다.
- 키워드 기반 자동 크롤링
  - 각 트랙의 키워드 관리 탭에 등록된 키워드를 순회하며 수집합니다.
  - 기업 뉴스룸이 등록된 키워드는 뉴스룸을 우선 조회합니다.
  - 뉴스룸이 없거나 신규 게시물이 없으면 네이버 뉴스 검색(보도자료 영역 포함)으로 대체 수집합니다.
- 기사 정보 추출
  - 제목
  - 언론사(또는 뉴스룸 발행 주체)
  - 발행일
  - 원문 링크
  - 검색된 키워드
- 수집 대상 판별(오탐 방지)
  - 목록에 표시된 날짜만으로는 신뢰하지 않고, 기사 상세 페이지의 발행일 메타데이터(`og:published_time` 등)를 직접 확인합니다.
  - 수집 기간은 실행 방식에 따라 다릅니다: **자동(매일, 트랙별로 시간 분산) 실행**은 "정확히 24시간 전 ~ 지금", **수동(메뉴 버튼) 실행**은 "당일 자정 ~ 버튼 클릭 시각"에 발행된 기사만 수집합니다.
  - 본문에 검색 키워드가 일정 횟수 이상 등장해야만 수집 대상으로 인정합니다(제목에만 잠깐 언급된 기사 오탐 방지).
  - 실행시간 보호를 위해 키워드당 상세 페이지 확인 건수에 상한을 둡니다.
- 중복 기사 제거
  - 같은 키워드로 뉴스룸과 네이버에서 중복 수집된 기사는 링크(URL) 기준으로 하나만 남깁니다.
  - 서로 다른 매체가 같은 보도자료/사안을 받아써 링크는 다르지만 내용이 사실상 같은 기사는, 제목+메타설명을 2-gram 유사도로 비교해 하나로 묶고 `기사건수`에 묶인 개수를 반영합니다(대표 기사는 가장 먼저 발행된 것). 이 그룹핑은 한 번의 수집 실행 안에서 새로 가져온 기사끼리만 비교합니다.
  - 자동수집(24시간 전~지금)과 수동수집(당일 자정~클릭 시각) 범위가 겹쳐 같은 기사를 다시 만나는 경우: 링크가 완전히 같으면 건너뛰고(패스), 링크는 다르지만 이미 저장된 행과 같은 사안이면(제목 기준 2-gram 유사도 비교) 새 행을 만들지 않고 그 행의 `기사건수`에 누적합니다.
- 수집 결과 집계
  - 키워드·수집 회차별 기사건수를 함께 기록합니다.
- 일일 요약 생성 (Claude API)
  - 그날 수집된 기사를 키워드별로 묶어 Claude API로 2~4줄 동향 요약을 생성합니다.
  - 키워드·수집범위별로 일일요약 탭에 누적 기록합니다.
- 주간 콘텐츠 후보 자동 제안 (Claude API)
  - 최근 7일치 일일요약을 모아 Claude API로 블로그 콘텐츠 후보 5~7건을 자동 생성합니다.
  - 후보별로 제목, 관련 키워드, 선정 이유, 라온시큐어 연결 포인트를 자동으로 채우고 담당자가 검토·수정합니다.
- 키워드 관리
  - 담당자가 키워드관리 탭에서 직접 키워드를 추가·비활성화할 수 있습니다(행 추가 + `사용여부` 칸에 `Y`).
  - 키워드별 기업 뉴스룸 URL을 등록할 수 있습니다.

## 시스템 구성
- Apps Script 수집 스크립트
  - Google Apps Script의 시간 기반 트리거로 실행합니다.
  - 수집 주기는 매일 1회, 트랙별로 시간을 분산해 실행합니다(기술 7시 / 경쟁사 8시 / 컨퍼런스 9시). 트랙 하나를 한 트리거에 몰아넣으면 Apps Script 트리거 실행 제한(6분)을 넘겨 타임아웃될 수 있어 트랙별로 트리거를 분리했습니다(2026-09-04).
  - `UrlFetchApp`으로 기업 뉴스룸 페이지 또는 네이버 뉴스 검색 결과를 조회하고 필요한 정보를 추출합니다.
- 키워드 관리 탭 (담당자 입력 가능, 트랙별로 별도 탭 — 키워드 등록/관리를 한 탭에서 모두 처리)
  - 수집할 키워드 목록을 Google Sheets에서 관리합니다.
  - 컬럼: `사용여부 | 키워드 | 기업뉴스룸 URL | 카테고리 | 등록일 | 비고`
  - 기업뉴스룸 URL이 비어 있으면 네이버 검색만 수행합니다.
- 뉴스 수집 탭 (1차, 트랙별로 별도 탭)
  - 자동 수집된 기사 정보를 누적 저장합니다.
  - 컬럼: `수집일시 | 키워드 | 제목 | 언론사 | 발행일 | 링크 | 기사건수 | 요약생성일시`
  - `기사건수`는 그 행(사안)으로 묶인 기사 수입니다. 같은 사안이 이후 수집(자동/수동 겹침 등)에서 다시 발견되면 새 행 대신 이 값에 누적됩니다.
- 일일요약 탭
  - 그날 뉴스 수집 탭에 쌓인 기사를 키워드별로 묶어 로컬 러너가 게이트웨이로 요약한 결과를 기록합니다.
  - 컬럼: `수집범위 | 키워드 | 기사건수 | AI요약 | 생성일시`
  - 그날 수집 기사가 없으면 러너가 요약을 건너뜁니다.
- 주간 콘텐츠 후보 탭 (2차)
  - 최근 7일 일일요약 탭 데이터를 로컬 러너가 게이트웨이로 분석해 콘텐츠 후보를 자동 생성하고, 담당자가 검토·수정합니다.
  - 컬럼: `주차범위 | 순위 | 제목 후보 | 관련 키워드 | 선정 이유 | 라온시큐어 연결 포인트`
  - 일일요약이 아직 하루치도 없어도(설치 직후 등, "일주일을 다 채워야만" 생성되지 않도록) 최근 N일간 뉴스수집 탭 원본 기사로 대체해 그때까지 쌓인 데이터만으로 후보를 생성합니다. 최근 N일 일일요약도 원본 기사도 전혀 없을 때만 후보 생성을 건너뜁니다.
- 로그 탭
  - 수집 실행 결과를 기록합니다.
  - 컬럼: `실행일시 | 트랙 | 대상키워드수 | 신규기사수 | 오류수 | 오류내용`
- 데이터 브릿지 Web App (Apps Script)
  - 로컬 러너가 시트를 읽고 쓰기 위한 창구. AI 호출은 하지 않습니다.
  - `doGet`: `todayNews`(오늘 수집분 키워드별 그룹), `recentSummaries`(최근 N일 일일요약), `weekNews`(최근 N일 원본 기사 키워드별 그룹 — 일일요약이 아직 없을 때 로컬 러너의 폴백용) 반환
  - `doPost`: `dailySummary`(일일요약 기록), `weeklyCandidates`(주간 후보 기록)
  - 스크립트 속성 `WEBAPP_TOKEN` 과 요청 `token` 파라미터가 일치할 때만 응답합니다.
  - 배포: 웹 앱(실행: 나 / 액세스: 모든 사용자).
- 로컬 러너 (사내망 Node 스크립트, `runner/summarize.mjs`)
  - AI 추론 담당. Web App 에서 데이터 수신 → 사내 게이트웨이 추론 → Web App 으로 결과 기록.
  - `daily`(일일요약), `weekly`(주간 후보), `selfcheck`(순수 로직 점검) 명령 제공.
  - 반드시 사내망(VPN 포함) 안에서 실행. 게이트웨이 키/Web App 토큰은 `.env` 에 보관(커밋 금지).

## 기술 스택 요약
- 실행 환경: Google Apps Script
- 데이터 저장: Google Sheets
- 자동 실행: Apps Script 시간 기반 트리거, 트랙별로 분리 (기술 7시 / 경쟁사 8시 / 컨퍼런스 9시)
- 웹 수집: Apps Script `UrlFetchApp`
  - 기업 뉴스룸: 사이트별 목록 페이지 파싱
  - 네이버: 뉴스 검색 결과 파싱
- HTML 파싱: Apps Script 문자열 처리 및 정규식 기반 추출
- 요약 처리
  - Phase 1: 기사 스니펫 기반 규칙 요약
  - Phase 2: Claude API를 사용한 일일요약(키워드별 동향 요약)과 주간 콘텐츠 후보 자동 생성
  - **하이브리드 구조**: AI 추론에 쓰는 사내 AI Gateway(LiteLLM, `https://litellm.ops.raonops.com`)는 사내망에서만 도달 가능하고 Apps Script(구글 서버)에서는 닿지 않는다. 따라서 추론은 사내망 **로컬 러너(Node)** 가 담당하고, Apps Script 는 로컬 러너가 시트를 읽고 쓰기 위한 **데이터 브릿지 Web App** 역할만 한다.
  - 게이트웨이 호출: 로컬 러너에서 OpenAI 호환 포맷(`/v1/chat/completions`, Bearer 인증)으로 Claude 호출
  - Claude 모델: `claude-sonnet-4-6` (ID는 점(.)이 아닌 하이픈(-) 표기여야 함; 게이트웨이 허용 모델은 `claude-haiku-4-5`/`claude-sonnet-4-6`/`claude-opus-4-8` 3개뿐)
  - 게이트웨이 API 키는 로컬 러너의 `.env`(`LITELLM_KEY`)에 저장(커밋 금지). Web App 인증 토큰은 Apps Script 스크립트 속성(`WEBAPP_TOKEN`)과 러너 `.env`(`WEBAPP_TOKEN`)에 동일하게 등록.

## 인증/보안 전략
- Google Sheets와 Apps Script는 담당자 Google 계정 권한 안에서만 접근하게 합니다.
- 시트 공유 권한은 최소 인원으로 제한합니다.
- Apps Script 프로젝트 편집 권한은 운영 담당자만 보유합니다.
- 사내 게이트웨이 API 키는 사내망 로컬 러너의 `.env`(`LITELLM_KEY`)에만 저장하고 저장소에 커밋하지 않습니다.
- 데이터 브릿지 Web App 은 스크립트 속성 `WEBAPP_TOKEN` 과 일치하는 요청만 처리하며, 토큰은 로컬 러너 `.env` 에만 둡니다.
- 게이트웨이는 사내망 전용이므로 추론 트래픽이 사내망을 벗어나지 않습니다.
- 원문 링크와 수집일시를 함께 저장해 데이터 출처를 추적할 수 있게 합니다.
- 외부 사이트 수집 시 과도한 요청을 방지합니다.
  - 하루 1회만 정기 실행
  - 키워드/사이트별 요청 간격 적용
  - 오류 발생 시 반복 요청 제한
- 개인정보를 수집하지 않습니다.

## Phase 1 개발 범위
- Google Sheets에 키워드 관리 탭 생성 (담당자 입력 가능)
- Apps Script로 매일 자동 수집
  - 기업 뉴스룸 우선 수집, 없으면 네이버 검색으로 대체
- 뉴스 수집 탭에 신규 기사 누적 기록 (동일 링크는 패스, 유사 사안은 기존 행에 병합)
- 기사 요약 생성(규칙 기반)
- 주간 콘텐츠 후보 탭 틀 생성 (담당자 수기 작성)
- 실행 로그 기록

## Phase 2 개발 범위
- 데이터 브릿지 Web App + 사내망 로컬 러너(하이브리드) 구축
  - Apps Script Web App(`doGet`/`doPost`)이 시트 데이터를 토큰 인증으로 주고받습니다.
  - 로컬 러너가 사내 게이트웨이로 추론하고 결과를 시트에 기록합니다.
- 일일요약 자동 생성
  - 그날 수집된 기사를 키워드별로 묶어 게이트웨이로 2~4줄 동향 요약을 생성하고 일일요약 탭에 기록합니다.
- 주간 콘텐츠 후보 자동 제안
  - 최근 7일 일일요약을 분석해 콘텐츠 후보와 라온시큐어 연결 포인트 초안을 자동 생성합니다.
  - 담당자는 자동 제안된 초안을 검토·수정만 하면 되도록 합니다.
- 알림 기능
  - 신규 기사 수집 시 담당자에게 이메일 또는 Slack으로 알립니다.
- 수집 범위 확장
  - 네이버 외 다른 포털(다음 등) 또는 검색 API 기반 수집을 검토합니다.
