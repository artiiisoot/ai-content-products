# 네이버 브랜드검색(브검) 모니터링 자동화 SPEC

등록된 브랜드 키워드에 대해 네이버 통합검색의 "브랜드검색" 영역을 매일 자동으로 크롤링하고, 이전 수집 결과와 비교해 변경사항이 있을 때만 결과와 캡처 이미지를 누적 기록하는 서비스입니다. Google Apps Script는 쓰지 않고, 로컬 Python 스크립트 + 로컬 대시보드(서버 실행 시 키워드 추가·수동 수집 버튼도 동작)로 구성합니다.

## 목적
- 담당자가 매번 네이버에서 브랜드검색 노출 여부와 소재를 수동으로 확인하지 않아도, 매일 자동으로 현황을 파악할 수 있게 합니다.
- 브랜드검색 소재(본문 타이틀·카피, 서브링크, 상품 리스트, 하단 스트립 등)가 변경되거나, 운영이 중단되거나, 신규로 운영을 시작한 시점을 놓치지 않고 기록합니다.
- 변경이 없는 날은 중복 기록하지 않아 목록을 깔끔하게 유지합니다.
- 수집 기록과 실제 노출 화면을 링크 클릭 없이 한 화면에서 바로 볼 수 있게 합니다.

## 핵심 기능 요약
- 브랜드 키워드 기반 크롤링 (자동수집 + 수동수집)
  - `keywords.json`에 등록된 브랜드 키워드를 순회하며 네이버 통합검색 결과를 조회합니다.
  - **자동수집**: 스케줄러가 매일 오전 9시에 실행합니다. 이 실행이 관측하는 범위는 "어제 오전 9시 ~ 오늘 오전 9시"(직전 자동수집 이후 하루치)입니다.
  - **수동수집**: 담당자가 필요할 때 직접 실행합니다. 관측 범위는 "당일 자정 ~ 실행 시점"입니다. 자동수집을 기다리지 않고 오늘 발생한 변경을 바로 확인하고 싶을 때 사용합니다.
  - 두 방식 모두 같은 판정 로직(신규/변경/동일/미운영전환)을 거치며, 결과 중복 시(캡처 이미지 해시 동일) 스킵됩니다 — 아래 "변경 감지 및 누적 기록" 참고.
- 브랜드검색 영역 식별 (`brand_search`)
  - 통합검색 결과에서 브랜드검색 광고 영역만 식별합니다. 이 영역은 `direct_link_area`(로고/홈페이지) / `brand_news_area`(새소식) / `desktop_light`(메인 타이틀·카피·서브링크·상품 리스트) / `light_plus_bottom_wrap`(하단 스트립) / `m_brand_channel`(브랜드 SNS 소식) 순서의 하위 블록들로 구성됩니다.
  - 이 중 "브랜드 SNS 소식"(`m_brand_channel`) 블록만 모니터링·캡처 대상에서 제외합니다. 나머지 블록(본문 타이틀, 서브링크 버튼, 상품 리스트, 하단 스트립 아이템)은 전부 캡처·비교 대상입니다.
- PC/Mobile 동시 수집 (디바이스별로 완전히 독립)
  - 네이버 브랜드검색은 광고주가 PC용/모바일용을 따로 켜고 끌 수 있고(실측 확인: 파수·소프트캠프·마크애니는 모바일 브랜드검색 자체가 없음), 페이지 구조(HTML 클래스명)도 PC(`search.naver.com`)와 Mobile(`m.search.naver.com`)이 서로 다릅니다.
  - 그래서 키워드마다 PC/Mobile을 각각 별도로 크롤링·판정·저장합니다 — 신규/변경/동일/미운영전환 판정, 콘텐츠해시, 최종확인일시가 모두 디바이스별로 독립입니다(같은 키워드라도 PC는 "동일", Mobile은 "미운영전환"처럼 서로 다르게 나올 수 있습니다).
  - Mobile 마크업엔 서브링크(`link_button_item`)·상품(`product_item`) 영역 자체가 없어(실측 확인) 그 두 필드는 항상 빈 값으로 저장됩니다. 타이틀(`title`)·카피(`desc_wrap`)·하단스트립(`premium_item`)·이미지는 PC와 마찬가지로 추출·캡처됩니다.
- 운영 여부 판정
  - 브랜드검색 영역 자체가 없으면(해당 디바이스 기준) **미운영**으로 판정합니다.
  - 브랜드검색 영역이 있으면 **운영중**으로 판정하고 소재 정보를 추출·캡처합니다.
- 소재 캡처 + 필드 추출 (핵심 산출물)
  - 브랜드검색 영역(SNS 소식 제외)을 실제 렌더링된 화면 그대로 스크린샷으로 캡처합니다. 본문 타이틀, 서브링크 버튼, 상품 리스트, 하단 스트립까지 한 이미지 안에 전부 담깁니다.
  - 동시에 4개 항목을 텍스트로도 각각 뽑아 구조화해 저장합니다: **타이틀**(`main_title`) / **카피**(`main_desc`) / **서브링크**(`link_button_item`, 목록) / **상품**(`product_item`, 목록) / **하단스트립**(`light_plus_item`, 목록). 대시보드에 이 4개 항목이 클래스명과 함께 각각 표기됩니다.
- 변경 감지 및 누적 기록 (핵심 로직)
  - 캡처 이미지 바이트 자체를 해시로 비교해 직전 수집 결과와 다른지 판단합니다(신규/변경/동일/미운영전환 분류의 기준).
  - "변경"으로 판정되면, 위 5개 필드(타이틀/카피/서브링크/상품/하단스트립)를 직전 레코드와 각각 비교해 **어떤 항목이 달라졌는지 라벨로 남깁니다**(`변경내역`, 예: `상품(product_item)`). 캡처 이미지는 달라졌는데 5개 필드가 전부 같으면(예: 상품 썸네일 이미지만 교체) "세부 항목은 동일 (이미지·레이아웃 차이로 추정)"으로 표기합니다.
  - 원문 링크(광고 클릭 추적 URL)는 소재가 그대로여도 요청마다 값이 달라지는 것이 실측으로 확인되어 변경 감지·비교에는 쓰지 않습니다(참고용으로 별도 저장은 계속합니다).
  - **신규 등록** (해당 키워드의 첫 수집, 운영중) → 결과 누적 + 캡처 이미지 저장
  - **변경 감지** (캡처 이미지 해시가 직전과 다름, 운영중) → 결과 누적 + 캡처 이미지 저장 + 변경내역 라벨링
  - **동일** (해시가 직전과 같음) → 새 레코드는 추가하지 않고 건너뛰되(중복 방지), 해당 키워드 최신 레코드의 `최종확인일시`만 오늘 날짜로 갱신해 "변경사항 없음"임을 표기합니다.
  - **미운영 전환** (직전엔 운영중이었는데 이번엔 영역이 없음, 또는 첫 수집부터 미운영) → "미운영"으로 표기만 하고 캡처는 하지 않습니다.
  - 이 판정 로직은 자동수집·수동수집 모두 동일하게 적용됩니다. 즉 자동수집 결과와 수동수집 결과의 캡처 이미지 해시가 같으면(같은 날 두 번 실행되어 소재가 그대로인 경우) 수동수집 건도 "동일"로 판정되어 새 레코드 없이 스킵되고 `최종확인일시`만 갱신됩니다.
  - 새 레코드는 항상 최신순(수집일시 내림차순)으로 조회되며, 대시보드 최상단에 표시됩니다.
- 대시보드 자동 생성
  - 매 실행 후 수집 기록을 **수집일시(날짜) 단위로 묶어 하나의 세트**로 정적 HTML을 다시 생성합니다. 날짜 제목(`YYYY-MM-DD 수집`) 아래, 그날 수집된 브랜드들이 나란히 배치됩니다.
  - 화면은 **현재 등록된 브랜드 개수만큼 컬럼으로 분할**됩니다(예: 3개 키워드 → 3분할, 최대 6열까지만 한 줄에 두고 그 이상은 다음 줄로 넘어갑니다). 키워드가 추가·비활성화되면 컬럼 수도 그에 맞춰 자동으로 바뀝니다.
  - 각 브랜드 컬럼엔 **PC/Mobile 전환 버튼**이 있어, 같은 카드 안에서 두 디바이스의 수집 결과(캡처 이미지·타이틀·카피 등)를 버튼으로 바로 바꿔볼 수 있습니다. 카드마다 독립적으로 전환되며, 해당 디바이스에 브랜드검색이 아예 없으면(예: 대부분 키워드의 Mobile) 그 탭은 "미운영"으로 표시됩니다.
  - 상단에 **현재 등록된 키워드별 운영 상태**(운영중/미운영/대기중)를 배지로 표시합니다.
  - 상단에 **새 키워드 입력 필드**와 **지금 수동 수집 실행 버튼**을 둡니다. `server.py`(로컬 대시보드 서버)를 통해 열었을 때만 실제로 동작합니다: 입력 필드는 `keywords.json`에 실제로 항목을 추가하고, 버튼은 그 자리에서 `collect("수동")`을 실행합니다. 둘 다 완료 후 페이지를 자동 새로고침해 결과를 바로 보여줍니다. 서버 없이 `dashboard/index.html`을 파일로 직접 열었을 때는 두 기능이 서버 연결 실패 메시지를 보여줄 뿐 나머지 화면(날짜별 브랜드 기록, 로그 히스토리)은 그대로 동작합니다.
  - **대시보드 / 로그 히스토리** 두 화면을 탭으로 전환합니다. 로그 히스토리는 `logs` 테이블을 표(실행일시/방식/대상/신규/변경/미운영전환/동일/오류수/오류내용)로 보여줍니다.
  - 각 브랜드 컬럼은 캡처 이미지가 위, 텍스트 정보가 아래로 오는 세로 배치입니다. 그 날짜에 해당 브랜드의 새 기록이 없으면(동일 판정이라 새 레코드가 없는 경우) 빈 칸으로 표시됩니다.
  - 각 브랜드 칸에 실제 캡처 이미지(`<img>`), 키워드·상태 배지, "변경" 건이면 바뀐 부분 안내문, 타이틀/카피/서브링크/상품/하단스트립 5개 필드(클래스명과 함께 라벨링, 라벨 위·값 아래 세로 정렬), 수집일시·최종확인일시, 원문 링크를 표시해 링크를 클릭하지 않고도 무엇이 왜 "변경"으로 잡혔는지 한눈에 확인할 수 있습니다.
- 키워드 관리
  - 담당자가 `keywords.json`을 직접 수정하거나, 서버 실행 중이면 대시보드 상단에서 브랜드 키워드를 추가·삭제할 수 있습니다. 삭제하면 `keywords.json`에서 해당 항목이 제거되고, 대시보드는 즉시 재생성되어 그 브랜드의 컬럼이 화면에서 사라집니다(누적된 과거 수집 기록은 `data.db`에 그대로 남습니다).

## 시스템 구성
- 크롤러 스크립트 (`collect.py`)
  - Playwright 헤드리스 Chromium으로 검색 결과 페이지를 실제 렌더링해 로드합니다.
  - 로드된 페이지의 HTML에서 브랜드검색(`brand_search`) 영역 유무와 타이틀/카피/서브링크/상품/하단스트립/원문링크를 정규식 기반으로 파싱합니다.
  - 브랜드 SNS 소식(`m_brand_channel`) 블록은 텍스트 파싱과 화면 캡처 양쪽 모두에서 제외합니다(스크린샷 전에 화면에서 숨긴 뒤, `.brand_search` 요소 전체를 PNG로 캡처).
  - `hashlib`로 캡처 이미지의 콘텐츠 해시를 만들어 직전 수집 결과와 비교합니다(신규/변경/동일/미운영전환 분류 기준).
  - "변경" 판정 시 5개 필드를 직전 레코드와 비교해 달라진 항목 라벨을 만듭니다(`diff_fields`).
- 로컬 스케줄러 (자동수집)
  - macOS `launchd`(plist) 또는 `cron`으로 매일 오전 9시에 `collect.py`를 실행합니다. 관측 범위는 어제 오전 9시 ~ 오늘 오전 9시입니다.
  - 실행 스크립트(`.sh`/`.plist`)는 한글 로그가 깨지지 않도록 UTF-8 인코딩을 명시합니다.
- 수동 실행 (수동수집)
  - 담당자가 터미널에서 `python collect.py --manual`로 직접 실행합니다. 관측 범위는 당일 자정 ~ 실행 시점입니다.
  - 별도 스케줄러 등록이 필요 없으며, 크롤링·판정·저장 로직은 자동수집과 완전히 동일한 `collect.py`를 공유합니다(플래그로 `records.수집방식`만 다르게 기록).
- 데이터 저장 (`data.db`, SQLite — Python 표준 라이브러리 `sqlite3`)
  - `keywords` 테이블: `사용여부 | 브랜드명 | 등록일 | 비고`
  - `records` 테이블(누적 결과): `id | 수집일시 | 최종확인일시 | 수집방식(자동/수동) | 키워드 | 운영여부(운영중/미운영) | 상태(신규/변경/미운영전환) | 타이틀 | 카피 | 서브링크(JSON) | 상품(JSON) | 하단스트립(JSON) | 이미지경로 | 원문링크 | 콘텐츠해시 | 변경내역`
    - `변경내역`은 상태가 "변경"일 때만 채워지며, 위 5개 필드 중 직전 레코드와 달라진 항목의 라벨을 쉼표로 나열합니다.
    - 동일 키워드의 가장 최근 레코드가 "현재 상태"이며, 변경이 없으면 새 레코드가 추가되지 않습니다.
    - `최종확인일시`는 매 실행마다 갱신됩니다. 동일 판정이 계속되면 `수집일시`(마지막 변경 시점)는 그대로이고 `최종확인일시`(가장 최근 확인 시점)만 갱신되어, "언제 바뀌었는지"와 "언제까지 변경 없음을 확인했는지"를 함께 볼 수 있습니다.
    - 조회 시 `ORDER BY 수집일시 DESC, id DESC`로 최신 기록이 항상 먼저 나오게 합니다(동일 초에 여러 키워드가 수집돼도 순서가 안정적입니다).
  - `logs` 테이블: `실행일시 | 수집방식(자동/수동) | 대상키워드수 | 신규건수 | 변경건수 | 미운영전환건수 | 동일(스킵)건수 | 오류수 | 오류내용`
- 캡처 이미지 저장 (`images/{키워드}/{수집일시}.png`)
  - 신규/변경 건의 브랜드검색 영역 스크린샷을 로컬 파일로 저장합니다. `records.이미지경로`는 이 파일의 상대경로를 가리킵니다.
- 대시보드 (`dashboard/index.html`, 정적 HTML)
  - `collect.py` 실행이 끝나면 `records`/`logs` 테이블을 읽어 HTML을 새로 씁니다 (템플릿 문자열, 별도 프레임워크 불필요).
  - 파일을 직접 열어도 조회는 되지만, 아래 로컬 서버를 통해 열어야 키워드 추가·수동 수집 버튼이 실제로 동작합니다.
- 로컬 대시보드 서버 (`server.py`, Python 표준 라이브러리 `http.server`만 사용)
  - `127.0.0.1:8765`에서만 수신(외부 네트워크 노출 없음). 프로젝트 폴더를 정적 파일 루트로 서빙해 `dashboard/index.html`, `images/`를 그대로 보여줍니다.
  - `POST /api/keywords`: 요청 본문의 브랜드명을 `keywords.json`에 append하고(중복이면 거부), 대시보드를 즉시 재생성합니다.
  - `POST /api/keywords/delete`: 요청 본문의 브랜드명을 `keywords.json`에서 제거하고(없으면 404), 대시보드를 즉시 재생성합니다. `data.db`의 과거 기록은 지우지 않습니다.
  - `POST /api/collect`: 그 자리에서 `collect("수동")`을 실행하고 결과 건수를 응답으로 돌려줍니다(완료까지 요청이 대기, 키워드 수만큼 몇 초~수십 초 소요).
  - 대시보드 JS는 두 버튼에서 이 두 엔드포인트를 `fetch`로 호출하고, 성공 시 페이지를 새로고침합니다. 서버가 꺼져 있으면(연결 실패) 그 사실을 화면에 표시합니다.

## 기술 스택 요약
- 실행 환경: Python 3
- 화면 캡처: Playwright(헤드리스 Chromium) — CSS 레이아웃을 픽셀로 렌더링하는 건 표준 라이브러리로 불가능해 이 부분만 예외적으로 외부 패키지를 씁니다. 설치: `pip install playwright && playwright install chromium` (최초 1회, Chromium 약 170MB).
- 데이터 저장: SQLite (`data.db`, 파일 하나, 표준 라이브러리 `sqlite3`)
- 이미지 저장: 로컬 파일시스템 (`images/`)
- 자동 실행: macOS `launchd` 또는 `cron` (매일 오전 9시) + CLI 플래그(`--manual`)로 수동 실행
- 텍스트 추출(표시용): 정규식 기반 HTML 파싱 (표준 라이브러리 `re`/`html`)
- 변경 감지: 캡처 이미지 바이트의 SHA-256 해시 비교 (`hashlib`)로 신규/변경/동일/미운영전환을 분류하고, "변경" 건은 타이틀·카피·서브링크·상품·하단스트립 5개 필드를 직전 레코드와 각각 비교해 어떤 항목이 바뀌었는지 라벨링합니다(`diff_fields`).
- 기록·이미지 통합 화면: 실행 후 자동 생성되는 정적 HTML 대시보드 (프레임워크 없이 템플릿 문자열로 생성)
- 로컬 대시보드 서버: Python 표준 라이브러리 `http.server`(`ThreadingHTTPServer` + `SimpleHTTPRequestHandler` 확장) — 새 외부 패키지 없이 정적 서빙 + 2개 API 엔드포인트만 얹음.

## 인증/보안 전략
- 모든 데이터(수집 기록, 캡처 이미지, DB 파일)는 로컬 디스크에만 저장하고 외부로 업로드하지 않습니다. 외부 공유 설정을 신경 쓸 필요가 없습니다.
- 데이터/이미지/대시보드 폴더의 파일 접근 권한은 담당자 계정으로 제한합니다.
- 외부(네이버) 요청은 자동수집 1일 1회 + 필요 시 수동수집으로 제한하고, 키워드별 요청 간격을 둬 과도한 요청을 방지합니다.
- 로컬 대시보드 서버는 기본값이 `127.0.0.1`(로컬호스트)만 바인딩입니다. `python3 server.py --host 0.0.0.0`로 실행하면 같은 네트워크의 다른 PC도 접속할 수 있게 됩니다 — 이 모드는 별도 인증이 없으므로, 신뢰하는 네트워크(사무실 내부망 등)에서 필요할 때만 켜고, 다 쓰면 다시 기본값(`127.0.0.1`)으로 끄는 걸 권장합니다.
- 개인정보를 수집하지 않습니다.

## Phase 1 개발 범위
- `keywords.json` 키워드 목록 관리 (담당자 직접 수정)
- `collect.py`로 매일 09시 자동 크롤링 (launchd/cron 등록, 어제 09시~오늘 09시 범위)
  - Playwright로 브랜드검색 영역 렌더링 후 SNS 소식 제외 캡처
  - 운영여부 판정, 신규/변경/미운영전환/동일 상태 분류
- `collect.py --manual`로 수동 크롤링 지원 (당일 자정~실행 시점 범위, 자동수집과 동일 판정 로직 공유)
- 신규·변경 건 SQLite 누적 기록 + 캡처 이미지 로컬 저장 + 5개 필드(타이틀/카피/서브링크/상품/하단스트립) 구조화 저장
- 변경 건은 직전 레코드와 필드별 비교해 `변경내역`(바뀐 항목 라벨) 기록
- 미운영 전환 건 상태 표기만 기록 (이미지 없음)
- 동일 건 스킵 (자동/수동 수집 간 중복 포함, 캡처 이미지 해시 기준) + `최종확인일시` 갱신으로 "변경사항 없음" 표기
- 실행 후 정적 대시보드 HTML(날짜별 세트 + 브랜드 컬럼 레이아웃) 자동 재생성 (최신순, 캡처 이미지 + 5개 필드 + 변경내역 포함)
- 실행 로그 기록 + 로그 히스토리 탭
- `server.py` 로컬 대시보드 서버: 키워드 추가 버튼(→ `keywords.json` 실제 반영) + 수동 수집 버튼(→ 그 자리에서 `collect("수동")` 실행) 제공
