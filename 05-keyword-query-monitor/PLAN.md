# 데일리 키워드 쿼리량 모니터링 PLAN

기준 문서: `SPEC.md`

`sample.jsx`는 참고만 하고 새 스크립트를 만듭니다. 인증 서명(HMAC), 429 재시도, 시트 헬퍼 같은 검증된 코드는 재사용하되, GA4/Google Ads/월간 키워드 모듈은 가져오지 않습니다. `sample.jsx` 리뷰에서 발견된 두 가지 함정(`"< 10"`을 숫자로 오인식, 키워드 매칭 실패 시 임의 폴백)은 처음부터 피해서 구현합니다.

## 개발 원칙
- 스크립트 1개, 시트 2개(키워드 탭 + 쿼리량 기록 탭)로 끝냅니다. 로그 시트, 알림 메일 등은 이번 범위에 넣지 않습니다.
- 키워드 하나 실패해도 전체 실행은 멈추지 않고, 실패 내용은 해당 키워드 행에 그대로 남깁니다.
- 같은 날짜에 같은 키워드를 다시 실행해도 중복 행이 생기지 않습니다.

## Phase 1 개발 단위

### P1-01. 시트 구조 생성
- 목표: 키워드 탭과 쿼리량 기록 탭을 자동 생성합니다.
- 구현 항목
  - `키워드` 탭 생성: `사용여부 | 키워드`, 초기값으로 라온시큐어/라온그룹/라온/라온메타/라온메타데미/옴니원/옴니원NFT/메타데미 8개 입력
  - `쿼리량` 탭 생성: `수집일 | 키워드 | PC 검색량 | 모바일 검색량 | 합계 검색량 | 표시제한여부 | 오류내용 | 수집시각`
  - 헤더가 없을 때만 생성(멱등)
- 주요 함수
  - `setup()`
  - `getOrCreateSheet_(ss, name, headers)`
- 완료 기준
  - 빈 스프레드시트에서 `setup()` 실행 시 두 탭과 헤더, 초기 키워드 8개가 생성됩니다.
  - 다시 실행해도 기존 데이터가 지워지지 않습니다.

### P1-02. 네이버 검색광고 API 연동
- 목표: 키워드 1개의 월간 PC/모바일 검색수를 안전하게 조회합니다.
- 구현 항목
  - HMAC-SHA256 서명 생성 후 `GET /keywordstool` 호출
  - 인증키(`NAVER_CUSTOMER_ID`, `NAVER_ACCESS_LICENSE`, `NAVER_SECRET_KEY`)는 스크립트 속성에서 읽기
  - 응답에서 요청 키워드와 **정확히 일치**하는 행만 사용 (일치하는 행이 없으면 오류로 처리, `list[0]` 폴백 금지)
  - `"< 10"`처럼 숫자가 아닌 값은 원문을 보존하고 `표시제한여부 = Y`로 표시 (임의로 `10`으로 변환 금지)
  - HTTP 429는 지수 백오프로 최대 4회 재시도, 그 외 오류는 즉시 오류로 기록
- 주요 함수
  - `fetchNaverKeywordStat_(keyword)`
  - `makeNaverSignature_(timestamp, method, uri, secretKey)`
  - `parseQcCnt_(rawValue)` — 숫자/`"< 10"`/빈값을 구분해 `{value, isLimited}` 형태로 반환
- 완료 기준
  - 정상 키워드는 PC/모바일 검색수가 숫자로 기록됩니다.
  - 저빈도 키워드는 `표시제한여부 = Y`로 표시되고 값이 `10`으로 둔갑하지 않습니다.
  - 매칭되는 키워드가 없으면 값은 비고 `오류내용`에 사유가 남습니다.

### P1-03. 일일 수집 실행
- 목표: 키워드 탭을 순회하며 쿼리량 탭에 오늘 날짜로 누적 기록합니다.
- 구현 항목
  - `키워드` 탭에서 사용여부 `Y`인 키워드만 조회
  - 오늘 날짜로 이미 기록된 키워드는 스킵 (날짜+키워드 키 기준 중복 방지)
  - 키워드 호출 사이 `Utilities.sleep()`으로 간격 확보
  - 키워드 하나가 실패해도 나머지는 계속 진행
- 주요 함수
  - `runDaily()`
  - `readActiveKeywords_(sheet)`
  - `buildExistingKeySet_(sheet, todayStr)`
- 완료 기준
  - 8개 키워드를 한 번 실행하면 쿼리량 탭에 오늘 날짜로 8행(성공/오류 포함)이 쌓입니다.
  - 같은 날 다시 실행해도 행이 중복되지 않습니다.

### P1-04. 자동 실행 트리거
- 목표: 매일 오전 9시에 `runDaily()`가 자동 실행되게 합니다.
- 구현 항목
  - 기존 동일 트리거 제거 후 재생성 (중복 방지)
  - 시간 기반 트리거: 매일, 오전 9시대
- 주요 함수
  - `setupDailyTrigger_()`
- 완료 기준
  - `setupDailyTrigger_()` 실행 후 프로젝트 트리거 목록에 `runDaily` 1개만 존재합니다.

### P1-05. 검증
- 검증 항목
  - 빈 시트에서 `setup()` → `runDaily()` 순서로 1회 수동 실행
  - 저빈도 키워드(예: 라온메타데미)가 `표시제한여부 = Y`로 정상 기록되는지 확인
  - 존재하지 않는 키워드를 임시로 추가해 `오류내용`에 사유가 남는지 확인
  - 같은 날 `runDaily()` 재실행 시 중복 행이 생기지 않는지 확인
- 완료 기준
  - 위 4가지 케이스가 모두 기대대로 동작합니다.

## 구현 순서
1. P1-01 시트 구조 생성
2. P1-02 네이버 API 연동 (키워드 1개 기준으로 먼저 검증)
3. P1-03 일일 수집 실행 (8개 키워드 전체로 확장)
4. P1-04 자동 트리거
5. P1-05 검증

## Phase 1 산출물
- Apps Script 코드 1개 파일
- `키워드` / `쿼리량` 탭
- 매일 오전 9시 자동 실행 트리거

## Phase 1 완료 기준
- 담당자가 `setup()` 1회 실행으로 초기 설치를 완료할 수 있습니다.
- 자동 실행이 매일 쿼리량 탭에 8개 키워드의 검색량을 누적 기록합니다.
- 저빈도 키워드의 `"< 10"` 값과 매칭 실패 오류가 왜곡 없이 그대로 기록됩니다.
- 키워드 하나가 실패해도 나머지 키워드 수집은 계속됩니다.
